# Діагностика кількості слів — 2026-10-22

Базовий commit: `60699e5e4d41ead88f835ef17a8069c2d8d830ea`.
Резервну копію повного репозиторію та точний знімок хмарного стану створено **до змін**. Архів і приватний знімок збережені локально в `outputs/count-diagnostic-2026-10-22/`; приватний знімок не публікується. SHA-256 архіву та всіх джерел є в JSON-звіті поряд із цим файлом. GitHub commit також зберігає повний початковий словник.

## Встановлена причина

Наведені у запиті числа 101 + 100 + 100 + 100 + 106 + 106 + 84 + 86 + 31 + 24 + 145 + 138 дорівнюють **1121**, а не 1097. Фактичне виконання всіх 12 скриптів з `index.html` дає **1121 запис і 1121 унікальний ключ, 0 дублікатів**.

Крім цього, `Progress.vocabulary(seed, stats)` додавав одне явно підтверджене користувачем особисте слово — `der Nebel` / `туман`. Воно зберігалося як `stats["der nebel"].customWord`, а не в окремій таблиці словника. У стані є 11 прихованих ключів; усі відповідають наявним словам. Тому до змін: **1121 + 1 − 11 = 1111 активних**. UI показував правильний результат.

Знайдено 7 історичних ключів статистики без точного відповідника в поточному словнику: старі позначення керування `ansehen als + nom.`, `schreiben an + dat.` і п’ять старих `(sich)`-ключів. У резервних копіях видно попередні назви/поділ рефлексивних конструкцій; поточний словник має відповідні виправлені/розділені конструкції. Ці ключі не створюють vocabulary records, не входять у лічильник, не видалені й не об’єднані з іншою статистикою в цій роботі.

## Аномалія 1121 → 1097

В історії за перевірений проміжок такого зменшення немає. Від commit `f53e235021fd1767b3517e4f358f5bf995210b25` (де corpus уже мав 1121) до базового commit жоден із 12 словникових файлів не змінювався. Доданий у цьому проміжку файл `backups/words-11-before-2026-10-22.js` — архів, він не завантажується застосунком і не замінює робочий файл.

`words-11.js` перевірено по всій історії цього файлу: 88 → 95 → 96 → 99 → 102 → 106 → 129 → 136 → 137 → 138 записів. У валідних послідовних версіях видалених ключів немає. Окремо зафіксовано стару синтаксичну помилку в `e8868cca…` (2026-10-20), виправлену через три хвилини в `d233dcb…`; вона не пояснює нинішні 24 записи і в актуальному файлі відсутня.

Різниця 24 точно збігається з розміром `words-9.js`: **1121 − 24 = 1097**. Цей файл створений у commit `4a6c1d98c371161911e052d78ba36f02d54e8d16`, відтоді не змінювався і побайтово збігається з оригіналом. Усі 24 записи присутні в runtime. ## Джерела runtime і кеш

- `index.html`: усі 12 вихідних `words-*.js`, тепер також `words-approved.js` з одним перенесеним особистим словом.
- `window.WORDS` → `rawSeed` → унікальні ключі `seed` → `Progress.vocabulary(seed, stats)` → `data` → фільтрація `hiddenWords`.
- `examples.js` і `verb-forms.js` доповнюють приклади/форми, не створюють словникових записів.
- `backups/` і JSON-звіти не завантажуються як vocabulary.
- `localStorage` містить сесію/офлайн-кеш хмарного стану. Старий `DATA_KEY` використовується лише для резервної копії legacy-даних; він не домішує старий словник до `seed`.
- У коді немає service worker або CacheStorage loader. Manifest містить параметри встановлення та іконки. Звичайний HTTP-кеш не потрібен для пояснення цифри 1111; її точно відтворено на знімку хмарного стану. Дані та кеш користувача не очищалися.

## Безпечне виправлення

Проблема полягала в неправильному зовнішньому підсумку й непрозорості джерел, а не в UI-арифметиці. `der Nebel` перенесено в канонічний GitHub corpus (`words-approved.js`) **точною копією всіх полів** з підтвердженого запису. Хмарні `customWord`, лічильники й ключ збережені; existing exact-key merge не додає другого екземпляра. Для нього окремо доданий авторський приклад у `examples.js`, не змінюючи оригінальні речення. Жоден старий словниковий файл не змінювався.

У ⚙ → «Склад словника» додано пояснення кількості: GitHub / особисті, ще не в GitHub / разом / приховані / активні. Особисті нові слова надалі є лише явно підтвердженими користувачем доповненнями cloud state; вони окремо обліковуються до перенесення в GitHub, не є прихованим автоматичним імпортом або незалежною неконтрольованою базою.

## Автоматична перевірка

`node scripts/audit-vocabulary.cjs` виконує фактичні скрипти з `index.html`, перевіряє синтаксис, фізичну кількість, унікальність, перезапис масиву та невключені root vocabulary files. Не підраховує слова регулярним виразом або кількість `de` у тексті. За потреби приватний експорт можна передати другим аргументом для повного розрахунку runtime/hidden/active; скрипт лише читає файли й нічого не записує в cloud/localStorage.

59 тестів пройшли. Нові тести звіряють source manifest, runtime, hidden filtering, UI, особисті записи, історичні ключі та незмінність snapshot. Ізольований Chrome на копії фактичного хмарного стану відтворив 1111 до і після, порівняв набір усіх runtime-ключів, повні per-word stats, цикл і hidden **на точну рівність**. Мережеве збереження в тесті заборонене. Перевірено ширини 320/390/1280 з великим текстом.

Змінені файли: `index.html`, `progress.js`, `app.css`, `examples.js`, `tests/trainer.test.cjs`, `tests/corpus-hashes.json`; нові `words-approved.js`, `scripts/audit-vocabulary.cjs`, `tests/vocabulary-counts.json` і цей MD/JSON-звіт. Supabase schema, функції, рядки прогресу й приховані слова не змінювалися. Приватна резервна копія не входить у commit.

Повторний read-only SQL-запит підтвердив: revision залишилася 640; MD5 повного state та hidden збіглися до/після діагностики. Усі 12 словникових файлів живого GitHub Pages також побайтово збіглися з початковим main.
